# Support personal and shared workspaces within one installation

People need a place for their own projects and a way to collaborate across teams. Each human therefore has a private personal workspace and can create or join multiple shared workspaces. Each project belongs to one workspace. This replaces the earlier one-organization-per-installation direction.

Collaboration happens in shared workspaces. Projects can be explicitly transferred from personal to shared workspaces and between shared workspaces. Shared workspaces use invitations and project permissions, and their owners control all projects they contain.

Accounts and permissions are local to the installation for the MVP. Cross-server collaboration remains a future feature. Keeping human identity separate from workspace membership leaves room for that extension.

See the [identity and access design](../design/identity-and-access.md) for the agreed rules and remaining questions.
