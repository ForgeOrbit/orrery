# Workspace-scoped outgoing webhooks with a transactional outbox and default-deny SSRF guard

Teams self-hosting Orrery want to connect board activity to external tools (Slack bridges, CI, automation) without building a bespoke GitHub App or plugin runtime in the MVP (issue #7, Option A). Outgoing HTTP webhooks create three lasting design commitments: who owns them, how reliably and safely they deliver, and what contract external receivers depend on.

Outgoing webhooks are **Workspace-scoped**, managed exclusively by `Workspace owner`s (or the owner of a `Personal workspace`), with explicit boolean scoping flags (`all_projects` + a `webhook_projects` join table, and `all_events` + an `events` filter over `ProjectActivityType`). Storing `all_projects` separately ensures that transferring a project out of a workspace removes its `webhook_projects` row without ever silently widening a single-project webhook into a workspace-wide subscription. Deliveries are enqueued in a Postgres transactional outbox (`webhook_deliveries`) inside the same transaction as `project_activity` and drained asynchronously with `FOR UPDATE SKIP LOCKED`, 5-attempt exponential backoff, a 10-second timeout, and automatic disablement after 10 consecutive exhausted deliveries. Payloads use a versioned (`version: 1`) metadata-only JSON envelope — omitting raw issue, comment, and knowledge Markdown bodies — and are signed with a server-generated `whsec_` secret encrypted at rest via `ORRERY_ENCRYPTION_KEY` ([ADR-0004](0004-encrypt-instance-secrets-at-rest.md)) using timestamped HMAC-SHA256 (`X-Orrery-Signature-256` over `${timestamp}.${rawBody}`). By default, delivery requires `https://`, disables HTTP redirects, and validates DNS-resolved IPs at connection time against loopback, private, link-local, and cloud-metadata ranges; operators targeting internal LAN receivers must explicitly set `ORRERY_WEBHOOK_ALLOW_PRIVATE_URLS=true`.

Project-scoped webhooks were rejected for MVP because small teams would duplicate the same endpoint across every project, while a `Workspace owner` already holds authority over all workspace projects so wildcard subscriptions cannot leak restricted projects. Best-effort in-request HTTP calls were rejected because slow or failing receivers would stall board writes and lose events on restarts, while an external queue (Redis/BullMQ) was rejected to preserve Orrery's single-database Docker deployment. Including full Markdown bodies in webhook payloads was rejected to prevent sensitive project text from leaking into third-party webhook logs; receivers needing full content can fetch it over REST with an explicit API key.
